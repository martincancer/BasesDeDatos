Consultas Multitabla
INNER JOIN en SQL Server

En esta clase empezamos a combinar información de varias tablas usando INNER JOIN. La idea es entender por qué hace falta unir tablas, cómo se relacionan mediante claves y cómo escribir joins simples y encadenados.

Por qué necesitamos consultas multitabla

Hasta ahora trabajamos con consultas sobre una sola tabla. Pero en una base de datos relacional, la información se distribuye entre varias tablas para evitar repeticiones y mantener la integridad. Por eso, para obtener datos completos, muchas veces necesitamos combinar tablas.

La separación entre tablas no es un problema: es parte del diseño. Justamente por eso existen los JOINs, que permiten volver a reunir la información cuando hace falta consultarla.
Ejemplo simple: Actor y País

La tabla Actor guarda el PaisID, pero no el nombre del país. Ese dato vive en la tabla Pais.

Actor

  • ActorID
  • Nombre
  • Apellido
  • FechaNac
  • FechaFall
  • PaisID

Pais

  • PaisID
  • Pais

Si queremos mostrar quién es cada actor y a qué país pertenece, necesitamos unir ambas tablas.

Concepto Descripción
Clave Primaria (PK) Identifica de forma única cada fila de una tabla. Ejemplo: PaisID en Pais.
Clave Foránea (FK) Columna que referencia la PK de otra tabla. Ejemplo: PaisID en Actor.
Integridad referencial Garantiza que la FK apunte a un registro existente en la tabla relacionada.

Qué hace INNER JOIN

INNER JOIN devuelve solamente las filas que tienen coincidencia en ambas tablas, según la condición indicada en la cláusula ON.

Si una fila de la tabla izquierda no tiene correspondencia en la derecha, no aparece en el resultado. Lo mismo ocurre al revés.
Sintaxis básica
SELECT columnas
FROM TablaA A
INNER JOIN TablaB B
  ON A.columna_fk = B.columna_pk
WHERE condicion_adicional
ORDER BY columna;
Cláusula Función
FROM TablaA A Indica la tabla principal del join.
INNER JOIN TablaB B Especifica la tabla que se va a combinar.
ON A.col = B.col Define la condición de combinación, normalmente FK = PK.
WHERE Permite agregar filtros después de unir las tablas.
ORDER BY Ordena el resultado final.
En SQL Server, escribir JOIN a secas equivale a INNER JOIN. Ambas formas son válidas y producen el mismo resultado.

Ejemplos básicos con INNER JOIN

Acá aparecen dos casos típicos: unir dos tablas relacionadas y usar alias para que la consulta sea más clara y más corta de escribir.

Ejemplo 1: Actores y su país de origen
SELECT
  a.Nombre,
  a.Apellido,
  p.Pais
FROM Actor a
INNER JOIN Pais p
  ON p.PaisID = a.PaisID;

Se usa a como alias de Actor y p como alias de Pais.

Resultado esperado (muestra parcial)
Nombre Apellido Pais
Sean Harris Reino Unido
Ignasi Abadal España
Bela Lugosi Hungría
Ejemplo 2: Películas con género y clasificación
SELECT
  p.TituloOriginal,
  p.FechaEstreno,
  g.Genero,
  c.Clasificacion
FROM Pelicula p
JOIN Genero g
  ON g.GeneroID = p.GeneroID
JOIN Clasificacion c
  ON c.ClasificacionID = p.ClasificacionID;

Acá se usan dos joins seguidos. También se ve que JOIN y INNER JOIN son equivalentes.

Joins encadenados

Cuando la información que querés mostrar está repartida en más de dos tablas, podés encadenar varios joins en una sola consulta.

La clave es seguir la ruta real de las relaciones. No todas las tablas se unen directamente entre sí: a veces hay que pasar por una tabla intermedia.
Ejemplo 3: Personaje, actor y país
SELECT
  pe.Personaje,
  a.Nombre,
  a.Apellido,
  pa.Pais
FROM Personaje pe
INNER JOIN Actor a
  ON a.ActorID = pe.ActorID
INNER JOIN Pais pa
  ON pa.PaisID = a.PaisID;

La relación real es: Personaje → Actor → Pais. Por eso el join se encadena en ese orden.

Resultado esperado (muestra parcial)
Personaje Nombre Apellido Pais
Solomon Lane Sean Harris Reino Unido
Vidal Gandolfo Ignasi Abadal España
Count Dracula Bela Lugosi Hungría
Si unís tablas que no están relacionadas directamente o escribís mal la condición del ON, el resultado puede duplicarse, quedar vacío o devolver datos incorrectos.

Resumen rápido

Esta tab resume las ideas más importantes de la clase para que te quede una guía corta de referencia al momento de escribir consultas con INNER JOIN.

Idea clave Resumen
INNER JOIN Devuelve solo las filas que tienen coincidencia en ambas tablas.
ON Indica la condición de unión, normalmente entre una FK y una PK.
Alias Hacen la consulta más corta, clara y evitan ambigüedades.
JOIN = INNER JOIN En SQL Server ambas formas son equivalentes.
Joins encadenados Se pueden usar varios joins seguidos para recorrer relaciones entre varias tablas.
Combinaciones extra INNER JOIN se puede combinar con WHERE, ORDER BY y TOP.
Cuando tengas dudas, pensá primero qué tablas necesitás, después cómo se relacionan y recién ahí escribí el join.
