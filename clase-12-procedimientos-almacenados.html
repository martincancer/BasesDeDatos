Procedimientos
almacenados

En esta clase vemos cómo agrupar instrucciones SQL en procedimientos almacenados para reutilizar operaciones, recibir parámetros y organizar la lógica de una base de datos.

Concepto general

Un procedimiento almacenado o stored procedure es un grupo de una o varias instrucciones SQL que se guarda dentro de la base de datos para poder ejecutarlo cuando se necesite.

Podemos pensarlo como una tarea con nombre: en lugar de repetir una consulta o una operación completa, se define una vez dentro de un procedimiento y luego se llama para ejecutarla.

Puede recibir datos

Acepta parámetros de entrada para adaptar su ejecución a cada caso.

Puede realizar operaciones

Dentro puede contener consultas, inserciones, modificaciones, eliminaciones u otras llamadas.

Puede devolver resultados

Puede devolver valores mediante parámetros de salida o un estado de ejecución.

Se guarda en la base

Queda disponible en SQL Server para quienes tengan permiso de ejecutarlo.

Los procedimientos almacenados ayudan a separar la lógica de datos de la capa de presentación de una aplicación.

Ventajas de utilizarlos

Son una herramienta muy utilizada porque concentran tareas habituales o complejas en objetos reutilizables dentro del servidor.

01

Rendimiento

Su lógica se almacena en el servidor y puede reutilizar el plan de ejecución, reduciendo trabajo repetido.

02

Seguridad

Se pueden otorgar permisos sobre el procedimiento y controlar quién lo ejecuta.

03

Reutilización

Evitan duplicar una misma operación en diferentes partes de una aplicación.

04

Mantenimiento

La lógica queda centralizada, documentable y más simple de modificar.

05

Transacciones

Pueden incluir BEGIN TRANSACTION, COMMIT y ROLLBACK para operaciones atómicas.

06

Menos tráfico

La aplicación solicita ejecutar una tarea sin enviar toda la lógica SQL cada vez.

Crear un procedimiento

La sentencia CREATE PROCEDURE define el nombre, los parámetros opcionales y el bloque de instrucciones que se almacenará en la base de datos.

Sintaxis general
CREATE PROCEDURE NombreDelProcedimiento
    @Parametro1 TipoDeDato,
    @Parametro2 TipoDeDato = valor_por_defecto
AS
BEGIN
    -- Lógica del procedimiento
END;
ElementoDescripción
CREATE PROCEDUREIndica que se está creando un procedimiento almacenado.
NombreIdentifica el procedimiento que se ejecutará después.
ParámetrosSon opcionales; se escriben con @, tipo de dato y, si hace falta, valor por defecto.
ASMarca el inicio del cuerpo del procedimiento.
BEGIN ... ENDDelimita las instrucciones SQL que componen su lógica.
Dentro de BEGIN y END se pueden incluir SELECT, INSERT, UPDATE, DELETE y otras instrucciones necesarias.

Ejecutar un procedimiento

Luego de crearlo en una ventana de consulta de SSMS, se llama con EXEC o EXECUTE. Si recibe parámetros, se les asignan los valores al invocarlo.

Llamada con parámetros
EXEC NombreDelProcedimiento
    @Parametro1 = 1,
    @Parametro2 = 'a';

Si un parámetro tiene un valor por defecto, no es obligatorio enviarlo al ejecutar el procedimiento.

EXEC

Forma abreviada habitual para ejecutar un procedimiento.

EXECUTE

Forma completa; produce el mismo resultado que EXEC.

Ejemplo: consultar un producto

Este procedimiento recibe el identificador de un producto y devuelve su nombre, precio de venta y stock.

Crear sp_Producto
CREATE PROCEDURE sp_Producto
    @productoid INT
AS
BEGIN
    SELECT
        Producto,
        PrecioVenta,
        Stock
    FROM Productos
    WHERE ProductoId = @productoid;
END;

El parámetro @productoid se utiliza en la condición WHERE para buscar el producto solicitado.

Ejecutarlo
EXEC sp_Producto @productoid = 1;
Al ejecutar el procedimiento con el identificador 1, SQL Server devuelve la información del producto que coincide con ese valor.

Resumen de la clase

Un procedimiento almacenado agrupa instrucciones SQL bajo un nombre para reutilizar una tarea de la base de datos.
